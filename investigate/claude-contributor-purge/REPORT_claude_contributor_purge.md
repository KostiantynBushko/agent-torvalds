# The "claude Claude" contributor — investigation and purge plan

**Date:** 2026-10-27
**Operator's request:** *"remove Claude footer in all PR so that I do not want
to see 'claude Claude' contributor in the agent torvalds repo"*

---

## 1. The finding in one line

The "claude Claude" contributor is **not** made by a pull-request footer. It
is made by a **`Co-Authored-By:` trailer in a commit message**, and exactly
**one** commit in the whole repository carries one.

Everything else the operator asked for is already clean.

---

## 2. What GitHub actually renders

The commit page of `6d330699c545fef9c97d5439632beeaf84f44f11` carries this
JSON in its payload:

```json
"authors":[
  {"login":"KostiantynBushko","displayName":"Ko…","isGitHub":true},
  {"login":"claude","displayName":"Claude Opus 4.8 (1M context)",
   "avatarUrl":"https://avatars.githubusercontent.com/u/81847?v=4",
   "isGitHub":false}
]
```

`login` is `claude`, the display name is `Claude Opus 4.8 (1M context)`, and
`isGitHub` is `false` — the trailer names no GitHub account, so GitHub draws
it with the generic avatar and links it to
`/commits?author=claude`. That is the **"claude / Claude"** entry the
operator sees in the repository's contributor list.

A PR body cannot produce this. GitHub builds the contributor list from commit
metadata; the body of a pull request is never part of it.

## 3. The offending commit

```
commit 6d330699c545fef9c97d5439632beeaf84f44f11
Author: Kostiantyn Bushko <kostiantyn.bushko@gmail.com>
Date:   Wed Oct 21 16:07:08 2026 +0300

    Initial commit: shodan-toolkit
    …
    Co-Authored-By: Claude Opus 4.8 (1M context) <noreply@anthropic.com>
```

It is the **root commit of the shodan-toolkit subtree**, and it entered
`master` through the `git subtree` merge:

```
3e4eab8  Add 'toolkits/shodan-toolkit/' from commit '26b1fb2895de048b15a653617cabcd88ea6f257b'
```

It is an ancestor of `master` and of **29 remote branches**.

> The SHA above is the one the commit had **before** the rewrite.  It is
> `759ba0b05292260058218e7053d8478ead58567e` now — see section 9.

A full scan of every ref in the clone — `git log --all --grep=claude` —
returns this commit and **nothing else**. There is no second offender.

## 5. Why a rewrite is the only way

There is no GitHub API that edits a commit message. The four things that
were considered:

| Option | Verdict |
|---|---|
| Edit the commit message through the REST API | **Impossible** — no such endpoint. |
| Re-open the PR / add a "corrected" commit | **Does not work** — the trailer is on the root commit of the subtree, and a later commit cannot remove it from an earlier one. |
| Delete the branch that holds it | **Does not work** — the commit is in `master`'s history, not in a branch. |
| **Rewrite the commit, then force-push** | **This is the way.** |

Because the offending commit is an ancestor of `master`, rewriting its
message changes the SHA of every one of the 129 commits after it. The
content does not change — only the commit messages and therefore the SHAs.

## 6. The plan

### 6.1 The tool

`self-development/investigate/claude-contributor-purge/`

| File | Role |
|---|---|
| `verify_no_claude.py` | The **check**. Walks the GitHub side (every PR title and body, every comment, every review comment, every commit of the default branch) and the Git side (every commit message of every ref). Reports PASS/FAIL per side. |
| `strip_claude_trailer.py` | The `git filter-repo` message callback. Removes the `Co-Authored-By: … Claude …` trailer and the `🤖 Generated with [Claude Code]` footer, and nothing else. |
| `test_strip_claude_trailer.py` | The test of that callback — 7 cases, driven the way filter-repo drives it. |
| `refresh_commit_shas.py` | The follow-up tool: substitutes the SHAs the rewrite made stale, using the `commit-map` `filter-repo` leaves behind. |
| `purge_claude_contributor.sh` | The **driver**. Baseline → scratch mirror clone → rewrite → verify → (optionally) force-push. Dry run by default. |
| `REPORT_claude_contributor_purge.md` | This document. |

### 6.2 Why the rewrite happens in a scratch clone

`git filter-repo` rewrites every ref in the repository it runs in, and it
**deletes the `origin` remote** as a safety measure. Running it in the
operator's working copy would leave that clone in a rewritten state with no
remote configured — recoverable, but not a state to leave the operator in.

So the driver clones a **mirror** into `/tmp`, rewrites there, verifies
there, and pushes from there. The operator's working copy is not touched by
the rewrite at all. Only the final `fetch`/`reset --hard` (which changes no
file, because the trees are byte-identical) touches it.

### 6.3 The rewrite

```bash
git filter-repo --force \
  --message-callback "$(cat strip_claude_trailer.py)"
```

The callback removes exactly two spellings:

```
Co-Authored-By: Claude Opus 4.8 (1M context) <noreply@anthropic.com>
🤖 Generated with [Claude Code](https://claude.com/claude-code)
```

**Verified on the rewritten commit:**

| | before | after |
|---|---|---|
| Author | `Kostiantyn Bushko <kostiantyn.bushko@gmail.com>` | *unchanged* |
| Author date | `2026-10-21 16:07:08 +0300` | *unchanged* |
| Committer | `Kostiantyn Bushko <kostiantyn.bushko@gmail.com>` | *unchanged* |
| Committer date | `2026-10-21 16:07:08 +0300` | *unchanged* |
| Subject | `Initial commit: shodan-toolkit` | *unchanged* |
| Body | … `Co-Authored-By: Claude …` | trailer removed, rest byte-for-byte |

### 6.4 The verification (dry run — all green)

```

PASS  master's commit count is unchanged (130)

```

The tree check is the one that matters: `master`'s tree after the rewrite is
byte-identical to `master`'s tree before it, so **no file in the repository

## 7. What the rewrite costs

This is the part the operator has to accept, and it is the reason the
approval is explicit.

### 7.1 29 branches are force-pushed

(The 32 was the number of *refs* — 29 branches plus the three local
`refs/heads` copies of branches that also exist as `refs/remotes/origin/*`.
The 26 branches that never carried the offending commit were not touched
at all.)

```
master
deployment-script                        (the open PR #56)
docs/{apt,db,github,git,linux,math,windows,xlsx}-toolkit-module-merged
feature/{shodan-toolkit,voice-toolkit,sqitch-database-migrations}
fix/{hitl-question-detection,readline-console-input,toolkit-alias-reference}
investigate/no-user-query-error
refactor/{apt,data-analysis,db,github,git,linux,math,os,shodan-toolkit-flat,
          toolkit-adapter-location,windows,xlsx}-toolkit-module
```

All of them are historical branches whose PRs are **already merged**. Their
content is unchanged — only the commit SHAs move.

### 7.2 29 merged pull requests get a new merge-commit SHA

The PRs merged after the shodan subtree landed (#28 … #57) had their merge
commits rewritten. **The content of every one of them is byte-identical** —
the trees are the same — but the *SHA* the PR page links to is new. A link
to an old SHA from outside GitHub (a bookmark, a chat message, a wiki) will
not resolve.

### 7.3 The SHAs recorded in the documentation go stale

`SELF_DEVELOPMENT_RULES.md` records **85** commit SHAs, and the other
markdown files record another ~94. The ones pointing at commits from the
shodan subtree onward will name commits that no longer exist.

**This is fixable, and it is the natural follow-up:** a script that walks
the rewritten history and rewrites the SHAs in the markdown from the old
value to the new one (`git filter-repo` writes a
`.git/filter-repo/commit-map` with exactly that mapping), and a pull request
that applies it. The mapping is known, and the rewrite is content-neutral,
so the substitution is mechanical and verifiable.

### 7.4 The one thing that cannot be un-done

A force-push of `master` is a history rewrite. The old commits stay in
GitHub's object store for a while and can be recovered by SHA, but they are
no longer reachable from any branch. **There is no `git revert` for this** —
it is not a change to the content of the repository, it is a change to the
identity of the history.

---

## 8. The recommendation

Do it. The operator's goal is explicit — no "claude Claude" contributor in
the repository — and there is no other way to reach it. The cost is
cosmetic: the trees do not change, the diffs do not change, the PRs stay
merged, the open PR #56 keeps its exact diff, and the only real follow-up
is refreshing the SHAs in the documentation.

The sequence, each step verified before the next:

1. **Commit** the tooling on the self-development branch
   `feature/purge-claude-contributor`.
2. **Push** the 29 rewritten branches (`purge_claude_contributor.sh --apply`).
3. **Verify** with `verify_no_claude.py` — both sides PASS.
4. **Refresh** the operator's clone: `git fetch --all --prune` and
   `git reset --hard origin/master`. No file changes — the tree is
   byte-identical.
5. **Follow-up PR**: refresh the SHAs in the markdown from the
   `commit-map` that `git filter-repo` leaves behind.

**The operator approved it, and it was executed.**  What actually happened
is recorded in section 9.

## 9. What actually happened

The plan was executed on **2026-10-27**.

| Step | Result |
|---|---|
| The rewrite | 264 commits rewritten. `master`'s tree is byte-identical before and after: `5f8ded2a750877c81a3fc13b880af7b14f709269`. The commit count is unchanged: 130. |
| The offending commit | `6d330699c545fef9c97d5439632beeaf84f44f11` → `759ba0b05292260058218e7053d8478ead58567e`. The trailer is gone; the author, the committer and both dates are unchanged. |
| The push | **29** branches force-pushed. **26** left alone — they never carried the offending commit. None added, none removed. |
| `master` | `21063431` → `0779228`. |
| The contributor | GitHub's commit page for the rewritten commit now names **one** author and no co-author. The repository's contributor list is a single entry. |
| The check | `verify_no_claude.py` reports **PASS** on both sides. |
| The documentation | 114 stale references refreshed in 15 files by `refresh_commit_shas.py` — see the `docs/refresh-stale-commit-shas` branch. |

**One thing the plan did not foresee.**  `filter-repo` rewrote *every*
commit in its scratch clone, not only the descendants of the offending one,
so its `commit-map` names a new SHA for the commits of the 26 branches that
were never pushed.  Those SHAs do not exist in the repository.  A naive
substitution would have pointed 103 references at commits that are not
there.

The refresh therefore carries a second guard: a substitution is made only
when the new SHA **resolves to a commit in this repository**.  161 of the
264 mapped pairs qualify; 103 do not, and the references to those commits
stay untouched — correctly, because the commits did not move.

**The old SHAs are still in GitHub's object store** and remain resolvable
by SHA for a while.  They are no longer reachable from any branch, so they
no longer contribute to the contributor list.
